# TR-Hash 200M remote token data

> **Current data path, completed release run.** The base replay described here
> produced the released 130B-exposure checkpoint. Reusing the launcher starts a
> new run or an exact resume; it does not continue the published model by
> implication.

The 200B pretokenized mixture is the immutable source repository for the 70B
quality replay. The replay runs without storing every token shard at once:
manifests are downloaded during preflight, binary shards are fetched lazily,
memory-mapped from local NVMe, and evicted from a bounded shared cache. The
tracked launcher defaults to 24 GiB; the example below deliberately uses 10.

```bash
TOKENIZED_DATA=hf://datasets/Pacific-i64/data-32k-200b-tokens \
TOKENIZED_CACHE_DIR=/workspace/token-cache \
TOKENIZED_CACHE_GB=10 \
TOKENIZED_PREFETCH_SHARDS=1 \
./scripts/vast_pretrain_tr_hash_200m_70b_replay.sh
```

Before training starts, the loader verifies that:

- every source manifest covers exactly its declared row budget;
- every referenced shard exists in the selected Hub revision;
- shard sizes match their manifests;
- SHA-256 digests match when generated by the current tokenizer pipeline;
- the dataset exposure exactly matches the optimizer-step schedule.

The final check prevents the trainer from silently restarting an exhausted
iterable and accidentally training on more passes than declared.

## Zero-copy 70B selection and replay

The replay-plan builder selects 70B unique tokens from the immutable 200B
dataset without copying or retokenizing any shard:

```bash
python -m scripts.build_tr_hash_70b_replay_plan \
  --tokenized-data hf://datasets/Pacific-i64/data-32k-200b-tokens \
  --cache-dir /workspace/token-cache \
  --output plans/tr_hash_70b_quality_replay.json
```

The default plan contains 70B unique tokens and 130B trained-token exposures:

| Source | Unique tokens | Passes |
|---|---:|---:|
| DCLM | 20B | 1 |
| FineWeb-Edu-Dedup | 25B | 2 |
| Stack-Edu | 8B | 2 |
| FineMath | 5B | 3 |
| InfiWebMath | 5B | 3 |
| Cosmopedia v2 | 7B | 2 |

Without a score file, shards are selected in stable manifest order. To select
the best-scoring shards within each source, provide a JSON object mapping each
relative shard path to a numeric quality score:

```bash
python -m scripts.build_tr_hash_70b_replay_plan \
  --tokenized-data hf://datasets/Pacific-i64/data-32k-200b-tokens \
  --quality-scores shard_quality_scores.json \
  --output plans/tr_hash_70b_quality_replay.json
```

Example score entry:

```json
{
  "corpora/fineweb_edu_dedup/tokens-00000.bin": 0.91
}
```

The builder refuses incomplete score coverage rather than mixing scored and
unscored shards. The generated `trained_tokens` value must be passed as the
training target:

```bash
TOKENIZED_DATA=hf://datasets/Pacific-i64/data-32k-200b-tokens \
TOKENIZED_PLAN=plans/tr_hash_70b_quality_replay.json \
TOKENIZED_CACHE_GB=10 \
./scripts/vast_pretrain_tr_hash_200m_70b_replay.sh
```

Use the exact `trained_tokens` written by the plan rather than assuming the
rounded example value; row alignment can add or remove less than one global
batch of tokens.

## Supervisor integration

Generate host configuration through the framework API; static machine-specific
Supervisor files are no longer versioned. Audit `/workspace/run_200m.sh`,
credentials, data access, disk capacity, and every environment variable before
calling `apply()`: an autostart program can start during `supervisorctl update`.

```python
from pathlib import Path

from complexity.training import SupervisorManager, SupervisorProgram

program = SupervisorProgram(
    name="tr_hash_200m_70b_replay",
    command=("/bin/bash", "/workspace/run_200m.sh"),
    directory=Path("/workspace/complexity-framework"),
    stdout_logfile=Path(
        "/workspace/complexity-framework/artifacts/tr_hash_200m_70b_replay.log"
    ),
    autostart=False,
    autorestart="unexpected",
)
manager = SupervisorManager()
manager.install(program)
manager.apply()
manager.status(program.name)
```

Start an inspect-only installation after verifying the tokenizer, Hub access,
and local cache volume with `manager.start(program.name)`. Use
`autostart=True` only for an audited unattended deployment.

For a clean machine-readable live view, follow the same append-only artifact
pattern as the Vision trainer:

```bash
tail -f artifacts/tr_hash_200m_70b_replay/metrics.jsonl
```

The launcher removes numbered resumable DDP checkpoints only after a successful
run has produced a non-empty `final/model.safetensors` export. Set
`CLEANUP_CHECKPOINTS_AFTER_SUCCESS=0` to retain them for debugging.
